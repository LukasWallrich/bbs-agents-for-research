Getting Started

Get oriented in a project

Point an agent at a folder you already understand and ask what is there, what looks important, and what may be missing.

Check: correct its map of the project before asking it to change anything.

Try it in: Codex, Claude Code, or another coding agent working in your project folder.

Extract objective details from papers

Give it a small folder of papers and ask for concrete data points: measurement scales used, sample sizes, countries, variables, manipulations, exclusion rules, or model specifications.

Check: require page or section pointers, then open the source for any detail you might reuse.

Try it in: Codex or Claude Code with the PDFs in a clearly named folder.

Get a working code scaffold

Ask for a first data-cleaning script, analysis template, simulation, or reproducible report structure.

Check: run it, inspect the assumptions, and test it on a case where you know what should happen.

Try it in: Codex or Claude Code, ideally with a small sample dataset and a clear analysis note.

Delegate repetitive browser tasks

Some agents can operate a browser or desktop while you watch, which can help with low-risk form filling or moving information between systems.

Check: review every field before submitting anything.

Try it in: Codex or Claude Code after installing a browser-control plugin or equivalent browser tool.

Habits

1

Give it enough context to be specific

Agents are at their best when they can inspect the real project: your folder structure, data dictionaries, code, draft, preregistration, paper set, or notes. The same is true in ordinary chat: models respond to the full context, not only the last sentence, and more relevant context usually produces more useful output.

2

Ground it in sources you can inspect

When an agent works in a local project, grounding usually means pointing it at the files it should use: the PDFs, scripts, data dictionaries, preregistration, or notes. Ask it to cite filenames and page, section, or line references so you can inspect the path from source to output.

Grounding helps you check the output. It does not mean the agent understood the source correctly.

3

Ask for a plan before you ask for output

A useful agent task has inputs, an output format, acceptance criteria, checkpoints, and known failure modes. Ask the agent to restate the task, propose a plan, and ask you any clarifying questions before it starts changing files or producing the final output.

The point is not to write a perfect prompt. It is to catch mismatched assumptions early and make the output easier to inspect.

4

Check what it hands back

Verification is not a moral afterthought. It is the whole reason the workflow works. Lean on both automated and manual checks, and where you can, a second pair of eyes that did not write the thing.

Automated. Run the code and write tests on cases where you know the answer: simulate data with an effect you put in and confirm the analysis recovers it, or check totals, ranges, and counts against the source file. Deterministic code is a cheap, repeatable second opinion.

Manual. Open the source for any claim or data point you might reuse. Do the numbers match the paper? Did it cite the right source for the right detail?

A fresh agent. Hand the output to a second agent that has no memory of how it was produced and ask it to find what is wrong. An agent reviewing its own work tends to agree with itself; a fresh run catches fabricated citations and unsupported claims the first one waved through.

Language models can sound confident when they are wrong, and publisher guidance puts responsibility on human authors, not AI tools.

Limits

Hallucination is not solved

Even strong models can produce false claims with fluent confidence. Treat citations, dates, statistics, and claims about specific papers as things to verify, not as settled facts.

Grounding improves traceability, not judgement

A source-linked answer can still misread the source. An extraction table with page references is easier to check, but it is not automatically correct.

AI can narrow thinking

Evidence on brainstorming suggests AI can raise the average creativity of individual ideas while reducing the diversity of ideas across a group. Use it as one voice in the room, not as the room.

Policies and data boundaries matter

Do not put confidential, identifiable, or restricted material into tools unless the data policy and project permissions allow it. Be especially careful with peer-review manuscripts: ICMJE advises reviewers and editors not to upload submitted manuscripts where confidentiality cannot be assured. For publication, disclose AI use according to the journal, funder, and institutional rules that apply.
